# ADR 0008: コントローラ名ベースの認可制御

- Status: Accepted(現状追認 — 2026-07-04 にコードから逆起こし)
- 関連: [ADR 0001](0001-twitter-omniauth認証と署名cookie自動ログイン.md), [specs/00-common.md](../specs/00-common.md)

## Context

本サービスの公開範囲は単純で、「誰でも見られるページ(トップ・お知らせ)」
「ログインユーザーが使うページ(それ以外ほぼ全部)」「管理者専用ページ(ユーザー管理・お知らせ編集)」
の3段階しかない。ロールベースの認可ライブラリ(CanCanCan等)を導入するほどの複雑さはない。

## Decision

1. `ApplicationController` の `before_action :auth` で全リクエストを検査し、
   **コントローラ名の文字列比較**で匿名アクセス可否を決める
   (`app/controllers/application_controller.rb#auth`)。
   除外リストは `home` / `sessions` / `infos` の3つ。それ以外は `login_required` を通す。
2. `login_required` は署名Cookieからユーザーを引き、
   - 見つからなければ root へリダイレクト(notice「ログインしてください。」)
   - `is_ban=true` なら logout へリダイレクト(alert「お使いのアカウントはブロックされています。」)
3. 管理者判定は `users.is_admin`(boolean)のフラグ1本で行い、
   `check_admin` を必要なコントローラで個別に `before_action` 宣言する。
   適用箇所: `UsersController`(全action)、`InfosController`(new/create/edit/update)。
   非管理者は root へリダイレクトする。

## Consequences

- 実装は数行で済み、認可の全体像が `ApplicationController` だけで把握できる。
- 除外リストが**コントローラ名の文字列**なので、コントローラのリネーム・追加時に
  認可漏れ/過剰保護が起きやすい(新規コントローラはデフォルトでログイン必須になる点は安全側)。
- `infos` はコントローラ単位で匿名許可した上でaction単位の `check_admin` を重ねており、
  「destroy はログイン不要だが管理画面導線がない」という隙間がある
  (`check_admin` の対象に destroy が含まれていない。経緯不明・バグの可能性あり)。
- リソース所有権のチェックは認可層ではなく各コントローラのクエリ条件で行う
  (例: `VideosController#set_video` が `user_id` を条件に含める)。
