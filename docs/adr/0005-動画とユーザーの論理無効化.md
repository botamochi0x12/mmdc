# ADR 0005: 動画とユーザーの論理無効化(is_show / is_ban)

- Status: Accepted(現状追認 — 2026-07-04 にコードから逆起こし)
- 関連: [ADR 0003](0003-ファイル名完全一致照合と3ユーザー閾値wanted昇格.md), [specs/02-video.md](../specs/02-video.md), [specs/10-user-admin.md](../specs/10-user-admin.md)

## Context

- 動画(`videos`)は `emms` → `mmd_objects` の親であり、wanted昇格判定
  (「何人のユーザーがこのファイルを使ったか」)の集計母体でもある。物理削除すると
  集計の根拠データが消える。
- ユーザー(`users`)は `credits.updated_by` や `credit_logs` から参照されており、
  物理削除すると監査履歴が壊れる。迷惑ユーザーは「排除」したいが「抹消」はできない。

## Decision

1. **動画の削除は `is_show=false` への更新(論理削除)**とする
   (`VideosController#destroy`, 一括削除は `Video.delete_by_ids` が `update_all(is_show: false)`)。
   物理DELETEは行わない。復活導線(is_showをtrueに戻すUI)は存在しない。
2. 表示・集計系のクエリは `is_show = true` を条件に含めて論理削除済みを除外する
   (`Video.set_total`, `Emm.get_emm_details`, `Video.get_dl_video_info` 等)。
3. **ユーザーの「削除」はBAN(`is_ban=true`)**とする(`UsersController#destroy`)。
   BANユーザーはログイン時に `login_required` で弾かれる([ADR 0008](0008-コントローラ名ベースの認可制御.md))。
   レコードと投稿データは残る。

## Consequences

- wanted昇格集計・貢献度ランキング・クレジット監査の整合性が削除操作で壊れない。
- **wanted昇格判定(`is_wanted`)は `is_show` を条件に含めていない**ため、
  論理削除済み動画のオブジェクトも「使用ユーザー数」にカウントされ続ける
  (仕様か漏れかは経緯不明)。
- データは増える一方であり、削除済み動画のemm・mmd_objectsも蓄積し続ける。
- ユーザー自身が自分のアカウントや投稿を完全に消す手段はない。
