# ADR 0004: 集計・照合クエリの生SQL実装

- Status: Accepted(現状追認 — 2026-07-04 にコードから逆起こし)
- 関連: [ADR 0003](0003-ファイル名完全一致照合と3ユーザー閾値wanted昇格.md), [specs/02-video.md](../specs/02-video.md), [specs/07-credit-download.md](../specs/07-credit-download.md)

## Context

動画一覧・emm詳細・クレジットDLでは、
`videos → emms → mmd_objects → wanteds → credits → authors` を跨いだ
多段JOIN + 3カラム複合キー結合 + GROUP BY + 条件付き集計が必要になる。
`wanteds` との結合は外部キーではなく `file_name`/`folder_name`/`extension` の値結合であり、
ActiveRecordのアソシエーションでは素直に表現できない。

## Decision

1. 集計・照合系のクエリは **ヒアドキュメントの生SQL**として実装し、
   `ActiveRecord::Base.connection.select_all` / `select_one` で実行する。
   置き場所は各モデルのクラスメソッド(`Video.set_total`, `Video.get_dl_video_info`,
   `Video.get_three_info`, `Emm.get_emm_details`, `EmmRegistService#is_wanted`)。
2. 値のバインドは `sanitize_sql_array` によるプレースホルダで行う(SQLインジェクション対策)。
3. MySQL方言(`GROUP_CONCAT`, `IF()`, `ORDER BY NULL`)を許容する。

## Consequences

- 複合キー結合と一括集計(`Video.set_total` は total/yets/wants/resolveds の4指標を1クエリで返す)が
  N+1なしで書ける。
- **DBがMySQL前提になる**(SQLite等へのテストDB差し替えは不可。テストもMySQL必須)。
- ActiveRecordのモデル層と乖離するため、スキーマ変更時にSQL文字列の追従漏れが起きやすい。
- `Video.set_total` の `#{ unless emm_id.nil? then 'and emms.id = :emm_id' end }` は
  文字列interpolationだが、埋め込まれるのは固定文字列のみで値はプレースホルダ経由のため
  インジェクションにはならない(ただし読み手を不安にさせる書き方ではある)。
- 集計結果はモデルの `attr_accessor`(total/yets/wants/resolveds)に格納され、
  DBカラムではないため、呼び出し側が `set_total` を呼び忘れると nil になる。
