# ADR 0002: emm/xml/mpj解析のサービス層同期実行

- Status: Accepted(現状追認 — 2026-07-04 にコードから逆起こし)
- 関連: [ADR 0003](0003-ファイル名完全一致照合と3ユーザー閾値wanted昇格.md), [specs/03-emm-upload.md](../specs/03-emm-upload.md)

## Context

MikuMikuDance系ツールのプロジェクトファイルには複数のフォーマットがある:

| 形式 | 生成元 | 実体 |
|---|---|---|
| `.emm` | MikuMikuEffect | Windows-31JのINIファイル |
| `.xml` | MikuMikuMoving | XML |
| `.mpj` | MikuMikuMoving | 先頭36バイトのヘッダ + zlib圧縮されたXML |

いずれからも「動画で使用したモデル・アクセサリ・エフェクトのファイルパス」を抽出して
`mmd_objects` に正規化する必要がある。

## Decision

1. 解析ロジックはモデルでもコントローラでもなく **`app/services/` のサービスクラス**に置く。
2. **継承で形式差分を表現する**:
   - `EmmRegistService` — 基底。INIパース(`IniFile`、`Object`/`Effect` セクションのみ)、
     `mmd_objects` 生成、wanted昇格判定を持つ
   - `XmlRegistService < EmmRegistService` — `analyze_emm` と `copy_file` を上書きし、
     `MMProject/Models` 配下の `Model`/`Accessory`/`Effect` の `File` 要素を抽出
   - `MpjRegistService < XmlRegistService` — `analyze_emm` を上書きし、36バイトシーク+
     `Zlib::Inflate` 展開後にXMLとして処理
   - `UpfileManageService` — アップロードファイルの拡張子で上記へ振り分けるファサード
3. 解析は**リクエスト内で同期実行**する(ジョブキューなし)。
   呼び出し元は `VideosController#create` → `UpfileManageService.save`。
4. アップロード原本は `secrets.save_dir_path` 配下へ
   `{user_id}_{タイムスタンプ}_{index}{拡張子}` の名前で保存する。
   emm形式はこの保存時に Windows-31J→UTF-8 変換し、パス区切り `\`→`/`、
   `#`→`＃`(INIのコメント記号誤認回避)の置換を行う。

## Consequences

- 形式追加は「継承クラスを1つ足して振り分けに1分岐足す」だけで済む。
- 同期実行のため、**巨大なemmや大量ファイルのアップロードはHTTPタイムアウトのリスク**がある
  (現状は小さなテキストファイルなので問題化していないと推定)。
- 解析失敗行は `Rails.logger.warn` に記録してスキップする方針のため、
  ユーザーには解析漏れが通知されない。
- `#`→`＃` 置換は保存ファイルにも及ぶため、原本とバイト一致しない
  (`full_path` にも `＃` が残る。表示時に戻す処理はない — 経緯不明、お茶を濁す旨のコメントあり)。
